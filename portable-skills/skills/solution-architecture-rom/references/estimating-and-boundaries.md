# Estimate readiness and boundaries

**Block numeric ROM** when unquantified dependencies could dominate effort: unknown equipment interfaces, undocumented signal semantics, undefined regulatory validation, unspecified full-scope rollout, or unowned operational support. An illustrative number that merely looks helpful is not permission to estimate.

**Conditional ROM** may be appropriate when a narrow software scope has measured work units (e.g., documented events, screens, workflows) and dependencies are limited or explicitly excluded. State the named units, an auditable low/high per workstream, the arithmetic and what forces re-estimation. Base all ranges on a *declared hypothetical planning assumption* unless independent benchmarks were supplied. Label synthetic examples as synthetic; never substitute them for actual rates.

Keep separate:
- Product configuration and workflow implementation
- Connectivity and tag semantics, often controlled by equipment specialists
- Enterprise integration and interfaces
- Testing/acceptance, installation and training
- Managed service, 24/7 support and lifecycle obligations

A non-binding ROM is a communication aid, not a procurement commitment. Human commercial and technical sign-off is required outside the skill.
